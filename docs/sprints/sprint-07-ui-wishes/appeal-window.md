# Окно обращения — как рисовать `card` и чат

Источник правды слева: [card.md](../../../requirements/severholod/card.md).  
Источник ленты справа: [generation.md](../../../concept/generation.md).  
Это спецификация отображения, не план задач и не код.

---

## 1. Каркас экрана

Шапка приложения (Рефлекс / Стол / Журнал / Создать обращение) — фикс сверху.

Под шапкой — **две колонки на всю оставшуюся высоту окна**. Никакого скролла страницы целиком.

| Колонка | Поведение |
|---------|-----------|
| Левая — документ `card` | Свой вертикальный скролл. Шапка обращения (R-id, статус стола, outcome, run) липкая внутри колонки или над скроллом |
| Правая — диалог | Колонка фикс на высоту экрана. Лента скроллится внутри. Поле ответа прибито к низу колонки |

Пока `run_status = running`, справа идёт живой поток. Слева слоты обновляются по `card_updated`, без перезагрузки страницы.

### Форма и JSON

В шапке левой колонки переключатель на два режима **одного и того же** `card`:

| Режим | Что это |
|-------|---------|
| **Форма** | Удобный документ: слоты, LED, id, кандидаты, evidences, договор, расчёт, решение. Диспетчер читает отсюда. |
| **JSON** | Тот же объект целиком, подсветка, моно, скролл. Для сверки схемы и отладки, не второй источник правды. |

Переключатель не меняет данные. Редактирование JSON руками не обещаем (пилот). Форма покрывает все поля из разделов ниже — «не извлечено» тоже рисуем, слот не прячем.

## 2. Легенда статусов привязки

Четыре слота с id: `customer`, `site`, `asset`, `history`.

| `binding.status` | Подпись | Цвет | Что обязательно показать |
|------------------|---------|------|---------------------------|
| `empty` | не извлечено | тусклый | только имя слота, без id |
| `mentioned` | упомянуто | пульс / нейтральный акцент | `mention`, evidences; id нет |
| `resolved` | опознано | циан | `binding.id` + `binding.label`; `mention` если был |
| `not_found` | не найдено | красный | `mention` **не стирать**; кандидаты пустые |
| `ambiguous` | несколько | янтарь | `mention`; список `candidates` (id, label, при необходимости `site_id`) |

Слоты без id (`problem`, `symptoms`, `desired_deadline`, `backup`): нет LED привязки. Пусто = «не извлечено». Есть `value` — показать значение. У срока ещё `parsed_at`, если код разобрал дату.

---

## 3. Свидетельство (`evidences[]`)

У каждого слота список. Пустой список не рисуем рамкой. Каждый элемент — строка:

| Поле | Как |
|------|-----|
| `kind` | факт / предположение / система |
| `source` | текст входа / отправитель / вложение / диспетчер / CRM / EAM / договор / ITSM |
| `confidence` | высокая / средняя / низкая |
| `fragment` | в кавычках, только если `kind = fact` |
| `record` | `система · id · подпись`, только если `kind = system` |

Несколько evidences — все, не «первый попавшийся».

## 4. Слоты фактов — полное покрытие

### 4.1. Клиент / объект / оборудование / прошлое

Одна карточка-слот, сверху вниз:

1. Имя слота + LED статуса.
2. Если есть `mention` — строка «в тексте: …».
3. Если `resolved` — крупно `id` (моно) и `label`.
4. Если `ambiguous` — список кандидатов, каждый id + label (+ площадка у актива).
5. Если `not_found` — явно «в реестре нет», mention жив.
6. Если `empty` — одна строка «не извлечено».
7. Блок evidences.

Особые случаи из card.md:

- Клиент `resolved`, объект `ambiguous` — два разных слота, не одно поле.
- Актив `not_found` (КМ-9) — заявка на площадку не подразумевается; mention остаётся.
- История `resolved` на T-884 — id тикета + тема; у актива может быть второе свидетельство `system` / ITSM.
- История `mentioned` («вчера мастер») без тикета — mention есть, binding empty или not_found после поиска.

### 4.2. Проблема / симптомы / срок / резерв

- `value` целиком.
- Срок: сырая фраза всегда; `parsed_at` второй строкой, если есть.
- Evidences так же.

## 5. Договор `contract`

| `status` | Показать |
|----------|----------|
| `empty` | «не запрашивали» (площадка не resolved) |
| `resolved` | `id`, `plan`, `response_sla`, `service_window`, `coverage[]`, `site_id` |
| `not_found` | «договора на площадку нет», Gold не выдумывать |

---

## 6. Расчёт `calculation`

Всегда видны три метрики: приоритет, SLA, дедлайн.

У каждой: `value` / `code` / `at`, `formula`, `arguments` (ключ=значение), `missing[]` если не пусто.

| `status` | Как |
|----------|-----|
| `blocked` | цифр нет, видны `missing` |
| `conditional` | «если площадка X — то …», без одного дедлайна как будто уже выбрали |
| `computed` | числа на месте |

`branch`: create / update / none — подпись ветки.

---

## 7. Решение `decision`

| Поле | Когда рисовать |
|------|----------------|
| `outcome` | чип: создать / обновить / уточнение / диспетчеру / согласование / отказ автоматики; пусто — «ещё нет» |
| `reason` | всегда, если не null |
| `grounds` | список слотов-опор |
| `questions[]` | карточки вопроса (`text`, `blocks`); пустой массив — не показывать секцию |
| `warnings[]` | код + текст, отдельной рамкой |
| `reply_draft` | если есть |
| `ticket_draft` | поля ITSM только при create/update |
| `itsm_dry_run` | accepted / would-id / persisted; иначе секции нет |
| `auto_in_prod` | да / нет / ещё нет |

Пока прогон идёт: outcome может быть пустой или старый; в шапке отдельно `run_status`.

## 8. Правая колонка — чат на всю высоту

Поток сверху вниз, как переписка, не dump после паузы:

1. **Вход** — пузырь канала (email / Telegram / звонок / ЛК): отправитель, время, текст (и вложение, если было).
2. **Думаю** — поток reasoning (`thought` / токены рассуждения). Тусклый курсив, курсор, можно свернуть.
3. **Тул** — карточка на каждую пару `tool_call` + `tool_result`.
4. **Ответ** — markdown (`message_delta` → `message_final`, либо один `message_final` после guard): заголовки, списки, жирный, код. Курсор, пока идут токены.
5. Реплика диспетчера — обычный пузырь пользователя, затем новый цикл 2–4.

Поле ввода внизу колонки. Пока `running` — отправка выключена. Заглушки «агент разбирает…» нет: сразу виден поток блоков.

### Событие → блок

| Событие | Блок в ленте |
|---------|----------------|
| первое открытие / `intake` | пузырь входа |
| `thought` / delta мысли | блок «Думаю», **токен за токеном**, свернуть можно |
| `tool_call` | карточка тула, статус «вызывается», JSON args |
| `tool_result` | та же карточка: статус ок/ошибка, summary, JSON result |
| `message_delta` | пузырь ответа, markdown копится, курсор |
| `message_final` | тот же пузырь без курсора, форматирование полное |
| `run_finished` | тонкая метка конца прогона (исход), не новый dump |
| `run_error` | красный блок ошибки |

Неизвестный `type` — серая заглушка с именем типа, ленту не ломаем.

### Карточка тула

| Что | Откуда |
|-----|--------|
| Техническое имя | `search_sites`, `search_assets`, `search_tickets`, `get_contract`, `calculate`, `update_card` |
| Бизнес-имя | Поиск площадок / Поиск оборудования / Открытые заявки / Договор / Расчёт / Запись карточки |
| Статус | вызывается / ок / ошибка |
| Параметры | JSON аргументов, раскрываемый |
| Ответ | `summary` + JSON `result` (items, query), раскрываемый |

Сырой JSON в чате нормален. В `card` его не копируем.

### Стрим и reasoning — что надо сделать

Сейчас в агенте `streaming=False`, reasoning урезан (`max_tokens: 256`). Мысль приходит блоком после шага. Так оставлять нельзя.

Надо:

- включить стрим вызова модели; **все** видимые тексты — токен за токеном: рассуждение и ответ (`thought` delta + `message_delta`);
- reasoning **включён явно**, с нормальным `effort` (не прятать и не экономить);
- не ужимать `max_tokens` рассуждения ради экономии — лимит достаточный, чтобы мысль не обрывалась на полуслове;
- UI рисует курсор, пока идут токены; тулы по-прежнему карточками (args/result не токенами).

Не ставить одновременно запрещённую пару OpenRouter `reasoning.effort` + `reasoning.max_tokens`, если шлюз снова даст 400: тогда effort + достаточный общий `max_tokens`, либо тот режим, который у провайдера даёт полный reasoning-stream.

Как это уже работало в соседнем продукте и что из доков 2026 ещё живо — [docpoint-stream.md](docpoint-stream.md). Коротко: UI копирует **pending-буферы** DocPoint (`thought`/`message_delta` копятся, тулы сразу карточками); backend стримит `astream`, не `ainvoke`. Deep Agents не обязателен.

## 9. Что не класть влево
