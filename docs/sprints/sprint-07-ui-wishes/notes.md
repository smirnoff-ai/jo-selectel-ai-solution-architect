## Общее: дешево и старомодно

Сейчас весь контур читается как админка: серф в заголовках, плоские коробки, пустое поле справа на форме, на столе огромные пустые корзины, в журнале «просто таблица». Нет плотности операторского пульта и нет ощущения современного тех-продукта.

Что хочется по всему, не по одному экрану:

- один жёсткий язык: графит, ледяной циан, янтарь на уточнении — не газетный IBM Plex Serif;
- глубина панелей (линия, свечение активного, не «карточка shadcn на чёрном»);
- удобство: меньше мёртвого воздуха, ясные статусы, кликабельные куски как приборы, не абзацы текста.

## Карточка обращения

Левая колонка должна быть **документом `card`**, не стопкой одинаковых Card.

Слоты как рельса приборов:

| Слой | Как видно |
|------|-----------|
| упоминание | что сказали, цитата |
| привязка | LED: empty / mentioned / resolved / ambiguous / not_found + id |
| договор / расчёт / решение | отдельные модули, не «ещё один серый блок» |

Точная раскладка и покрытие всех полей `card`: [appeal-window.md](appeal-window.md).  
Слева переключатель **форма / JSON** одного объекта. Форма — полное удобное покрытие слотов; JSON — просмотр того же документа.

Правая колонка — **чат на всю высоту экрана**, не заглушка «агент разбирает…» и потом весь трейс разом. Левая колонка скроллится сама.

Живой поток, как в Cursor / Claude:

1. токены рассуждения (тусклый поток, можно свернуть);
2. тул: имя, аргументы, статус, короткий summary;
3. токены ответа markdown, курсор в конце;
4. параллельно слева слоты загораются по `card_updated`.

Контракт событий уже есть в [generation.md](../../concept/generation.md) (`thought`, `tool_call`, `tool_result`, `message_delta`). В UI это не доехало: hang, затем dump.

**Агент / стрим (надо сделать):** reasoning включён явно, с effort; не экономить на max_tokens мысли. Вызов модели стримить. В чате токен за токеном: думаю и ответ. Сейчас `streaming=False` и `reasoning.max_tokens=256` — это как раз то, что менять.

**Порядок тулов:** `update_card` (упоминания) → поиски (только чтение) → `update_card` (привязки) → `get_contract` → `calculate` → `update_card` (договор и расчёт). Тихого добора и прозрачного пересчёта нет.

Ориентир реализации (не код): как в AI DocPoint — pending-буферы чанков + карточки тулов сразу. Разбор и сверка с доками 2026: [docpoint-stream.md](docpoint-stream.md). Каркас Deep Agents оттуда не тащить.
