# Журнал использования AI

## Инструменты

Cursor-агент — мой основной инструмент: каркас, backend, frontend, документация. OpenRouter / Qwen 3 Coder — модель агента в рантайме. Langfuse — локальный контейнер для трасс (опционален: без него карточка собирается, просто нет observability).

## Как я вёл разработку

Я начал не с кода, а с пакета требований под вымышленного заказчика «СеверХолод»: функциональная спека экранов, контракт API мока, JSON карточки, сценарии приёмки S1–S4. По своей AI-Driven методологии из этого выросли concept-доки, ADR и roadmap из восьми спринтов; каждая задача шла через plan.md → реализация в Cursor → summary.md.

Порядок: сначала мок без LLM, затем каркас и API обращений, агент со SSE, UI, приёмка и demo. Два контура — curl к моку отдельно от прогона агента — я заложил сознательно: справочники отлаживаются без модели.

MVP (спринты 01–06) я закрыл за день короткими сессиями. Часть решений сознательно упростил под timebox: код добирал пропущенные поиски, guard переписывал исход, финал собирал structured JSON. После живого UI и трасс Langfuse — спринты 07–08: живой стрим, Langfuse v4, карточный цикл «поиск read-only → запись update_card», голос модели без guard.

AI генерировал каркас и черновики; согласование плана, accept-скрипт, поведение Qwen на трассах и финальные формулировки промпта — моя проверка и правки.

## Где AI ускорил

1. **Контракт мока и сид** — агент разложил пакет заказчика в HTTP-сервис с тестами 0/1/N и dry-run ITSM; меньше ручной сверки полей и id.
2. **Каркас FastAPI / Next и экраны** — по functional-spec и card.md: логин, стол, журнал, форма, карточка со слотами; быстрее, чем писать с нуля.
3. **System prompt и action space** — skill harness-construction: роль, границы, каталог тулов. Plan/summary спринтов и concept-доки — черновики агента с моим ревью, не «сгенерировал и забыл».

## Где пришлось править

Агент и observability менялись волнами, не одним решением. В sprint 04 `create_agent` на OpenRouter зависал ~90 с — я временно ушёл на ручной `run_tool_loop` с `bind_tools`; Langfuse подключал вручную (CallbackHandler ломался на связке LangChain 1 + SDK 2). В sprint 06 добавил `complete_catalog`: Qwen пропускал поиски, код добирал CRM/EAM/ITSM после цикла — accept S1–S4 стал зелёным, но модель могла «молчать» и получать данные бесплатно.

Sprint 07 откатил упрощения: вернул `create_agent` + `astream_events` v3 на `ChatOpenRouter` (reasoning через `effort`, не `ChatOpenAI` + `base_url` — иначе мысли в чате пропадают); Langfuse поднял до v4 с CallbackHandler. Убрал `complete_catalog`, ввёл `ToolStrategy(Finale)` и переименовал `patch_facts` → `update_card`: поиски только читают, карточку пишет модель. Sprint 08 снял Finale и guard — финал это markdown-отчёт модели и `card.decision`, код не переписывает исход; расширил `search_tickets` (не обязателен `asset_id`), `grounds` — фразы, не пути слотов.
