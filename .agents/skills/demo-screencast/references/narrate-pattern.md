# Синхронизация голоса и экрана — паттерн `narrate`

## Проблема (как ломали синхронизацию в прошлый раз)

```js
// ❌ НЕПРАВИЛЬНО
await say("Переключаемся на СФМ");   // показывает субтитр, ждёт TTS-длительность
await page.goto("/inbox/sfm");        // навигация (1-3 сек)
await page.waitForLoadState("networkidle");
```

При записи ffmpeg подставляет mp3 по времени появления субтитра. К моменту, когда голос читает «Переключаемся на СФМ», экран ещё показывает прошлую страницу. Когда навигация завершится, голос уже замолчал.

## Правильно

```js
// ✅ ПРАВИЛЬНО
await narrate(
  "Переключаемся на сотрудника службы финансового мониторинга.",
  async () => {
    await role("sfm", sfm1.id);
    await goto("/inbox/sfm");
  },
);
```

`narrate` делает всё одновременно:
1. Ставит субтитр.
2. Добавляет сегмент в audio timeline с текущим `start_ms`.
3. Запускает `action()` параллельно.
4. Ждёт `max(ttsDuration + 400ms, actionDuration)`.
5. Субтитр не убирает — следующий `narrate` / `chapter` его заменит.

## Правила

1. **Каждое значимое действие оборачивайте в `narrate`.**  
   Если внутри action несколько последовательных операций — они будут проиграны под одну длинную реплику. Нормально, если суммарно они укладываются в ~6-10 секунд.

2. **Action должен укладываться в длительность TTS.**  
   Длинные операции (waitForURL, polling, reload in loop) лучше разбить на подглавы или переместить подготовку **перед** narrate:

   ```js
   // ✅ Подготовить экран заранее, а narrate только описывает увиденное
   await goto("/dashboard");
   await page.waitForLoadState("networkidle");
   await narrate("Дашборд — это сводка KPI и воронка процессов.");
   ```

3. **Для «немых» переключений контекста используйте `wait(ms)`**, не `narrate` без action.

4. **Глава (`chapter`) — отдельно от реплик.**  
   `chapter("1. Подача заявки")` — всплывашка сверху ~1.5 сек, после неё можно сразу делать `narrate`. Субтитр в это время пустой.

## Структура реплики (UX-правила)

- **Одна мысль на реплику.** 1-2 предложения, 10-25 слов.
- **Не дублируйте то, что очевидно на экране.** Объясняйте **зачем**, не **что**.
  - ❌ «Нажимаем кнопку „Отправить заявку“.»
  - ✅ «Заявка уходит в процесс, и мы видим её карточку с хронологией.»
- **Говорите в настоящем времени от первого лица мн. числа** («Открываем…», «Видим…»).

## Расчёт таймингов

Движок делает pre-synth всех реплик через edge-tts и замеряет длительность каждой `seg_NN.mp3` через ffprobe. Длительность реплики ≈ длина текста × скорость TTS. Для `ru-RU-SvetlanaNeural` средняя скорость ~15-17 символов в секунду.

Если реплика короткая (< 3 сек), а action длинная (≥ 5 сек), то вы получите **тишину в середине сцены**. Либо разбейте на два `narrate`, либо добавьте ведущей/хвостовой паузы (`buffer` аргумент `narrate`):

```js
await narrate("Короткая реплика.", longAction, { tailMs: 3000 });
```

## Пример корректной сцены

```js
// Глава
await chapter("2. Экспертиза СФМ");

// Подготовка контекста (без озвучки)
await role("sfm", sfm1.id);
await goto("/inbox/sfm");

// Реплика 1 + действие
await narrate(
  "Эксперт открывает задачу и видит готовое мотивированное суждение.",
  async () => {
    await click("table tbody tr:first-child");
  },
);

// Реплика 2 + действие
await narrate(
  "Если нужны дополнительные документы — эксперт запрашивает их у уполномоченного работника.",
  async () => {
    await click('label:has-text("Запросить документы")');
    await fill(
      'textarea[name="docs_request_text"]',
      "Прошу предоставить устав ЮЛ.",
    );
    await click('button:has-text("Завершить задачу")');
  },
);
```

## Anti-patterns

- `narrate(...)` без `action` когда следом идёт долгое действие → рассинхрон.
- Два подряд `narrate` с коротким текстом и долгой подготовкой между ними → голос за кадром.
- `page.click(...)` вместо `click(...)` → курсор не движется, зритель не видит куда кликнули.
- `chapter` во время реплики → всплывашка перекроет контент.
