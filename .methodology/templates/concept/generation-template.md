## 3. Модель продуктовых событий

Сырой протокол фреймворка **не** отдаём в UI. Есть маппер (один на фреймворк) → продуктовые события.

| Вопрос | Решение |
|--------|---------|
| Имя типа | [открытая строка + fallback / закрытый enum] |
| Обязательные поля | `[type, source, ts, payload]` |
| Неизвестный тип в UI | [дженерик-карточка / игнор / ошибка] |

Базовый словарь (дополнять, не выдумывать лишнее заранее):

| `type` | Смысл | Стримится? | В историю? |

| `user` | сообщение пользователя | [ ] | [ ] |
| `assistant` | финальный ответ | [ ] | [ ] |
| `assistant_chunk` | дельта токенов ответа | [ ] | [ ] |
| `tool_call` | вызов инструмента | [ ] | [ ] |

## 4. Стриминг токенов

| Вопрос | Решение |
|--------|---------|
| Контракт «final после chunks» | [backend **обязан** прислать финальный `assistant` после серии chunk] |
| Reasoning | [chunk + final / только final / нет] |
| Текст субагента | [только chunk до `subagent_end` / есть финальный `subagent_message`] |
| UI | [аккумулирует delta в pending-блоке, заменяет на final] |

## 6. Что пишется в видимую историю

Тот же формат события для invoke и stream. Отличается **момент и состав** записи.

| Класс событий | Stream → UI | Stream → история | Invoke → история |
|---------------|:-----------:|:----------------:|:----------------:|
| Chunks (токены) | [да] | [обычно нет] | [нет] |
| Финалы (`assistant`, `reasoning`) | [да] | [да] | [да] |
| Tools / subagent | [да] | [да / нет] | [обычно нет / да] |
