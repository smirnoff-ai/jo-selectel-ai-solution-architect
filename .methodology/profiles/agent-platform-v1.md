# Профиль `agent-platform-v1`

> Именованное **предложение** ответов для агентного продукта с чатом и tools.
> **Статус:** ✅ Для предложения агентом
> **Опыт:** AI DocPoint (`monolit-docpoint`), не норма канона.

| Поле | Значение |
|------|----------|
| Id | `agent-platform-v1` |
| Когда предлагать | Есть LLM-агент, диалог в UI или API, набор tools. Пилот или первый контур без второго агента-потребителя снаружи процесса. |
| Когда не предлагать | Нет агента. Или сразу нужен enterprise-контур: MCP наружу, обязательные LLM-guards, HITL, мультимодальный вход — лучше пустой шаблон или будущий `agent-enterprise-v1`. |
| Опыт / источники | DocPoint vision §5, harness QA v1, ADR-0003/0005/0006/0009/0010/0015 |

## Развилки

| Шаблон и раздел | Развилка | Наш ответ | Почему | Когда не брать |
|-----------------|----------|-----------|--------|----------------|
| harness §6 | SDK и gateway | Один адаптер чата + один HTTP-gateway к моделям. LiteLLM не обязателен. В DocPoint — LangChain/Deep Agents и OpenRouter. | Меньше движущихся частей на пилоте; смена модели = строка в реестре. | Корп. политика требует Azure-only / on-prem gateway — заменить узел, сохранить «один вход». |
| harness §6 | Где крутятся чат-модели | Внешний API по умолчанию. Локальный vLLM/Ollama — опция, не default. | Быстрый старт, каталог моделей. | Данные нельзя отдавать наружу — локальный инференс. |
| harness §6 / rag §4 | Эмбеддинги и rerank | **Отдельно** от чат-LLM. Другой хост допустим и желателен. | Другой SLA, можно TEI локально при облачном чате. | Крошечный корпус без семантического поиска — RAG-дока нет. |
| harness §7 | Промпт-менеджмент | Файлы в git — source of truth. Observability (Langfuse и аналоги) — трассы, датасеты, eval, **не** CMS промптов. | Ревью в PR, воспроизводимый деплой, нет скрытой правки прода. | Команда промптов живёт только в CMS и не коммитит файлы — гибрид с явным экспортом в git. |
| harness §8 | Промпт vs skills | System prompt (роль, границы) **и** skills по требованию (алгоритм, шкала, сценарий). Не «только один промпт на всё». | Длинные процедуры не раздувают system. | Один короткий агент без сценариев — можно только prompt. |
| harness §9.1 | MCP продуктовых tools | In-process обёртки. MCP-сервер — когда появится **второй** потребитель (другой агент, внешняя среда). MCP в skills-router IDE — про разработчика, не про runtime. | На пилоте лишний контур. | Сразу несколько рантаймов или внешние агенты заказчика. |
| harness §10 | Три контура | UI-история (наши таблицы) ≠ checkpointer фреймворка ≠ observability. Связь чата и checkpoint — id потока, без подмены одной ленты другой. | Reload UI не зависит от внутренностей фреймворка; трассы не путают с чатом. | Нет диалога (batch-only) — UI-истории может не быть. |
| harness §10 | Долговременная память | Нет user-memory cross-thread в первой версии. Сжатие контекста — средствами фреймворка, не свой суммаризатор «на всякий случай». | YAGNI. | Продукт — персональный ассистент с памятью о пользователе. |
| harness §11 | Multimodal | Не принимаем, пока ТЗ явно не просит. Записать «нет» в harness. | Иначе хранение и трассы всплывут в середине. | Вход — фото, PDF, голос. |
| security §1 | Уровень защиты | Пилот: промпт + by-design (read-only tools, явные id). Guards, лимитеры, HITL — если контур production или есть запись во внешние системы. | Честный accept рисков пилота. | Production с недоверенным интернетом — не брать этот ответ. |
| generation §1–2 | Транспорт и режимы | Основной UI — `stream` по SSE. `invoke` — для API/batch. Режим на чате, mismatch — ошибка конфликта. | Один пайп событий; прокси не буферизует при правильных заголовках. | Инфра запрещает SSE — WebSocket, тот же словарь событий. |
| generation §3–6 | События и история | Открытый `type` + fallback-карточка. Final после chunks обязателен. Chunks — в UI live, в историю обычно только финалы. | UI не ломается на новом type; история не распухает от delta. | Нужен полный forensic replay каждого токена — тогда писать chunks. |
| generation §7 | Structured output | Явно назначить, кто кладёт `data` в финал (main / subagent / finalizer). Не надеяться, что оркестратор «сам донесёт». | Иначе отчёт субагента теряется в markdown main. | Нет structured output. |
| rag §6 | Funnel | Сначала детерминированный lookup, затем semantic search, не «загрузи всю базу». Safety-valve на большой текст. | Prefetch корпуса одним tool не работает на реальном объёме. | Корпус крошечный и всегда влезает в один ответ. |
| frontend-design / ux | Чат | Per-event live expand → auto-collapse. Фоновый стрим на другом табе живёт. Новый чат — lazy create на первой отправке. | Предсказуемая лента, как у IDE-агентов. | Нет чата. |

## Что профиль сознательно не фиксирует

Конкретные id моделей и цены, вендор СЭД, доменные тексты промптов, выбор Deep Agents vs другой каркас (каркас — развилка vision/ADR, не этого профиля), Qdrant vs другой движок ( rag-шаблон спрашивает движок; профиль требует только «эмбеддинги отдельно и funnel»).
