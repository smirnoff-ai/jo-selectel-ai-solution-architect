# Профили рекомендаций

Профиль — именованный набор **уже выбранных ответов** на развилки концепт-шаблонов.

Это **не** правило (`alwaysApply`) и **не** шаблон. Шаблон спрашивает, что решить. Профиль предлагает обычные для нас ответы. Человек утверждает профиль целиком, частично или отказывается.

В каноне методологии до этого пакета такого объекта не было. Ближайшие аналоги (список «что перенести из DocPoint», зашитый стек в conventions, пометки «пример» в шаблонах) профиль не заменяют.

---

## Как агент онбординга применяет профиль

1. На шаге 0 по типу продукта выбирает уместный профиль (агентный чат + инструменты + опционально RAG → `agent-platform-v1`).
2. Кладёт ответы профиля в черновики концепта как **предложение**, не как факт.
3. Спрашивает одно: берём целиком / вот отклонения / профиля нет, идём по шаблонам с вопросами.
4. В шапке каждого концепт-дока пишет id профиля и перечень отклонений. Позже смена профиля читается без археологии чатов.

Не устраивать допрос по каждой строке шаблона, если профиль утверждён. Спрашивать только то, чего нет в ТЗ и что ломает профиль.

## Новый профиль

Скопировать [profile-template.md](profile-template.md). Id в `kebab-case`. Каждая строка таблицы обязана ссылаться на развилку существующего шаблона. Не добавлять в профиль то, чего шаблон не спрашивает.
